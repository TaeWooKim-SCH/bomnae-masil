# 봄내마실 데모 시나리오

> R4-05 초안. 온라인 시연 1회와 오프라인 시연 1회를 같은 흐름으로 연습한다.
> 데모 기준 시각은 `DEMO_NOW=2026-08-01T14:00:00+09:00`이다.

## 0. 시연 전 5분 점검

1. Cloudtype 배포 주소의 `/health`를 열어 서버를 깨운다.
2. 온라인 시연 기기에서 카카오맵과 배포 화면을 새로고침한다.
3. 데모 세션과 진행 중 퀘스트를 초기화한다. 데모 가게 코드 `#51`을 준비한다.
4. `DEMO_NOW`가 8월 1일 토요일 14:00으로 설정됐는지 확인한다.
5. 발표자 1명, 화면 조작자 1명, 타이머 1명을 팀 안에서 정한다. 시연 조작은 최소 2명이 연습한다.

비상 문장: **"네트워크 이슈로 로컬 데모로 전환하겠습니다."**

## 1. 온라인 시연 — 입력부터 대시보드까지

### 1-1. 문제와 서비스 소개

- **화면:** 발표 슬라이드 1~2장
- **발표 문장:** "춘천의 오늘 할 수 있는 활동 정보는 여러 사이트에 흩어져 있고, 골목 가게는 새 방문자를 만날 기회가 적습니다. 봄내마실은 오늘의 외출 하나를 활동·가게 미션·버스 안내·기록으로 묶어 추천합니다."
- **클릭:** 서비스 홈으로 이동

### 1-2. 출발 조건 입력

- **화면:** 홈
- **조작:** 만 14세 이상 확인 → 관심사 선택 → 행정동 선택 → 정류장은 `잘 모르겠어요` 유지 → 시간 창과 예산 선택 → `추천 받기`
- **발표 문장:** "GPS를 수집하지 않습니다. 먼저 행정동을 고르고, 정류장을 고르면 더 정확하게 계산합니다. 모르면 가장 적합한 정류장을 골라 `○○ 정류장 기준`이라고 분명히 보여드립니다."

### 1-3. 퀘스트 카드 비교

- **화면:** 추천 카드 3장
- **조작:** 첫 번째 카드의 점수 구성과 가게 미션을 보여 준 뒤 상세로 이동
- **발표 문장:** "갈 수 있고 시간·예산에 맞는 활동만 먼저 남긴 뒤, 그 안에서 상권 기여 30%, 관심사 25%, 버스 접근성 20%, 시간 15%, 예산 10%를 합산합니다. 그래서 시민에게 불편한 곳을 억지로 권하지 않고, 좋은 후보 중 골목에 더 도움이 되는 가게를 앞세웁니다."

### 1-4. 이동·미션 확인과 시작

- **화면:** 퀘스트 상세
- **조작:** 활동 장소, 미션 가게, 출발 정류장, `퀘스트 시작` 버튼을 차례로 보여 준다.
- **발표 문장:** "버스 정보는 데이터가 보장하는 범위만 안내합니다. 300번, 7개 정거장, 약 25분처럼 노선·정거장 수·예상 소요시간을 보여 주고, 시간표나 실시간 정보는 운영 이관 뒤 BIS 연동으로 보강합니다."
- **상태 확인:** `recommended → started`

### 1-5. 가게 인증

- **화면:** 수행·인증
- **조작:** QR 탭을 먼저 보여 준 뒤, 준비한 4자리 코드를 입력해 인증한다.
- **발표 문장:** "가게 방문은 QR 또는 4자리 코드로 확인합니다. 카메라가 어려운 경우에도 같은 미션을 끝낼 수 있습니다."
- **상태 확인:** `started → stamped`, 포인트 `+40`

### 1-6. 활동 기록과 완주

- **화면:** 기록
- **조작:** 문답 칩을 최소 1개 선택 → AI 초안 생성 → 수정 가능한 기록을 저장한다.
- **발표 문장:** "기록은 활동 내용을 바탕으로 초안을 만들고 사용자가 직접 고칠 수 있습니다. 실명이나 연락처는 AI에 보내지 않습니다."
- **상태 확인:** `stamped → recorded`, 기록 `+40`, 완주 `+20`, 누적 `100점`, 칭호 해금

### 1-7. 시청용 대시보드

- **화면:** 정책 대시보드
- **조작:** 접근성 지도와 저유입 상권 레이어를 켠 뒤 KPI 4개를 보여 준다.
- **발표 문장:** "개인에게는 오늘의 외출을, 시청에는 추천과 방문의 익명 집계 결과를 제공합니다. KPI는 방문 전환율 40% 이상, 저유입 상권 추천 비중 50% 이상, 탐색 시간 3분 이내, 실행 가능성 100%를 목표로 봅니다. 시범 운영 시뮬레이션 데이터는 실제 운영값과 구분해 표시합니다."

## 2. 30초 보조 시나리오 — 신청형 강좌

> 최신 수기 씨드 `#49`가 준비된 경우에만 실행한다. 준비되지 않으면 이 시나리오는 생략한다.

1. 추천 카드에서 신청형 활동의 `개강 D-n` 표시를 보여 준다.
2. 상세에서 오늘 할 일인 `신청 · 장소 미리 가보기 · 근처 가게 미션`을 설명한다.
3. 발표 문장: "마감일 데이터가 없으므로 마감 임박이라고 말하지 않고, 개강일까지 남은 날짜만 정확하게 보여 줍니다."

## 3. 오프라인 전환 시나리오

1. 비상 문장을 말한 뒤 로컬 스택으로 전환한다.
2. `sync_local.sh`로 복사한 데이터와 로컬 서버를 사용한다.
3. 온라인 흐름과 동일하게 홈 → 추천 → 상세 → 시작 → 코드 입력 → 기록 → 대시보드를 진행한다.
4. QR 촬영은 생략하고 4자리 코드 입력으로 바로 인증한다.
5. AI 기록 생성이 느리면 저장된 결과 또는 템플릿 초안을 먼저 보여 준다.

## 4. 심사 질의 대응

| 질문 | 답변 |
|---|---|
| 왜 상권 기여가 가장 큰 30%인가요? | 갈 수 있는지·시간·예산·관심사는 먼저 하드 필터와 나머지 점수로 보장합니다. 조건을 만족한 좋은 후보끼리 골목에 도움이 되는 가게를 우선합니다. |
| GPS를 쓰지 않으면 위치가 부정확하지 않나요? | 행정동과 선택 정류장이라는 두 단계 입력으로 정밀도를 확보합니다. 정류장을 모르면 추천의 기준 정류장을 화면에 표시해 추정임을 숨기지 않습니다. |
| 버스 시간표는 왜 없나요? | 현재 데이터가 보증하는 노선·정거장 수·추정 소요시간만 제공하며, 시각표·실시간·배차 정보는 운영 이관 뒤 BIS 연동 로드맵으로 둡니다. |
| 개인정보는 어떻게 보호하나요? | 로그인과 GPS 수집 없이 익명 세션만 사용하고, 만 14세 이상 확인, 기록 전체 삭제, AI 입력 최소화 원칙을 적용합니다. |

## 5. 배포 전 결정·확인 항목

- **버스 문구 충돌:** `AGENTS.md`에는 "약 N분 간격 운행" 표기가 있으나, `docs/10-architecture.md`·`docs/25-screens.md`·R4-05 이슈는 배차간격 표기를 금지한다. R2가 데모·화면·발표에서 사용할 문구 하나를 확정해야 한다.
- **KPI 실값:** 발표 슬라이드의 실제 KPI 숫자와 화면 캡처는 본선 데이터가 준비된 뒤 채운다. 현재는 목표치·시뮬레이션 표시만 사용한다.
- **역할 배정:** 발표자·화면 조작자·타이머를 리허설 전에 이름으로 확정한다.

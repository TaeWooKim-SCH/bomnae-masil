# 봄내마실 — 역할과 협업

> 전원 필독. 원칙은 하나다: **역할 = 폴더 = 산출물.** 두 사람이 같은 파일을 고치는 상황을 처음부터 만들지 않는다.

## 1. 역할 한눈에

| 코드 | 역할 | 담당 (제안) | 소유 폴더 | 만드는 것 |
|---|---|---|---|---|
| R1 | 프론트엔드·디자인 | 최우혁 | `frontend/` | 화면 6종 전부, 지도, QR/코드 인증 화면 |
| R2 | 백엔드·인프라 | 김태우 | `backend/` (services 제외) | API 11개, DB 구조, 배포, 오프라인 스택 |
| R3 | 데이터·점수 | 최서준 (팀장) | `pipeline/`, `services/scoring/` | 데이터 10종 적재, 접근성 점수표, 5지표 점수, 대시보드 지도 데이터 |
| R4 | 조립·AI | 우영찬 | `services/quest_builder/`, `services/llm/` | 퀘스트 조립(걸러내기·빈결과 방지), AI 문안·기록, 데모 대본, 발표 자료 |

각자 "하지 않는 것"이 곧 경계다:
- **R1**: 서버 내부·데이터를 고치지 않는다. 데이터가 이상하면 이슈로 던지고 자기 레인을 유지한다
- **R2**: 점수 산식과 AI 문구 내용에 관여하지 않는다. R4의 조립 함수를 호출만 한다
- **R3**: 화면·API를 만들지 않는다. 점수는 함수로 제공한다. **환승 없이 갈 수 있는지 판별은 R3만 한다** (다른 사람은 결과 조회만 — 두 군데서 계산하면 반드시 어긋난다)
- **R4**: 점수 산식 내부와 DB 구조를 건드리지 않는다 (필요하면 R2·R3에게 요청)

**백업 페어: R1↔R4, R2↔R3.** 한 명이 아프거나 막히면 페어가 이어받는다. 그래서 통합 때마다 페어에게 15분 "실행 워크스루"(내 코드 받아서 켜보기)를 한다. 데모 시연 조작은 반드시 2명 이상이 연습해 둔다.

## 2. 담당 확정 전 검증 (7.29까지, 반나절)

직함이 아니라 검증된 스킬로 확정한다. 실패해도 계획이 있으니 부담 없이:

| 대상 | 과제 (각 1~2시간) | 안 되면 |
|---|---|---|
| R1 | ① 가짜 데이터로 카드 목록 화면 ② 지도에 마커+선 긋기 ③ QR 카메라 스캔 | QR은 4자리 코드 입력으로 대체(이미 설계에 있음), 지도는 마커만 |
| R4 | 가짜 점수 함수로 퀘스트 카드 3장 만드는 미니 조립 코드 | R2가 조립 코어를 맡고, R4는 AI 문안·데모 대본·발표에 집중 |

팀장 규칙: 팀장(R3)은 통합 진입 판정과 범위 축소 결정을 맡되, **판정은 미리 정한 체크리스트 확인**으로만 한다(자기 작업을 자기가 봐주는 상황 방지). 발표 자료는 R4가 만들고, 발표자는 대회 전에 정해서 연습 시간을 확보한다.

## 3. 저장소 규칙

- **저장소는 하나다.** R3·R4 코드가 `backend/` 안에 있어도 문제없다 — 폴더 단위로 주인이 있고, 코드 연결은 한 방향 화살표(`routers → quest_builder → scoring`)로만 한다. 남의 부품은 공개된 함수만 가져다 쓴다.
- **CODEOWNERS**: 폴더별 주인이 등록돼 있어 PR을 열면 주인이 자동으로 리뷰어가 된다. (팀원 GitHub ID 확정 후 주석 해제 필요 — 이슈 등록됨)
- **브랜치**: `main` 하나 + 작업 브랜치 `feat/<이슈번호>-<역할>-<요약>`. 작업 브랜치 수명은 반나절 이하 — **자주 합쳐야 통합이 가벼워진다.** 3시간 넘게 안 합친 브랜치는 위험 신호
- **머지**: squash(합칠 때 커밋 1개로 뭉침) 통일. 리뷰 필수는 계약 문서와 `models/` 변경뿐, 자기 폴더는 스스로 머지
- **통합 1시간 전 "머지 마감"** 콜 — 통합 시간은 합치는 시간이 아니라 확인하는 시간이다
- 충돌이 나면 먼저 올린 사람이 아니라 **그 폴더 주인이 해결**한다

## 4. 미리 약속하는 것 4가지 (Day 0 동결)

4명이 서로 기다리지 않고 달리려면, 부품이 만나는 접점을 먼저 확정해야 한다:

| # | 약속 | 누가 → 누구 |
|---|---|---|
| ① | API 명세 (`30-api-contract.md`) — 화면↔서버의 모든 요청·응답 형식 | R2 → R1 |
| ② | 점수 함수 형식 + 접근성 점수표 구조 | R3 → R4 |
| ③ | 대시보드 지도 데이터 형식 | R3 → R1 |
| ④ | 조립 함수 형식 (`build_quests` — 빈 결과일 때 규칙 포함) | R4 → R2 |

동결 후 변경하려면 해당 관리자 승인 + 단톡 공지가 필요하다. "일단 바꾸고 알리기" 금지.

이 약속이 있으면 각자 **가짜 데이터(목, mock)**로 자기 부분을 완성할 수 있다. 예를 들어 R1은 서버가 없어도 약속된 형식의 가짜 응답으로 전 화면을 만들고, 통합 때 진짜로 바꿔 끼운다.

## 5. 이슈와 마일스톤

**이미 45개 이슈가 등록돼 있다** (라벨 R1~R4, 마일스톤 4개, 각 이슈에 완료 기준 포함). 본선 당일 이슈 쓰느라 시간 쓰지 않기 위해서다.

- **마일스톤 = 통합 게이트 4개**: M0 배선(대회 전) → M1 추천이 뜬다(H12) → M2 전체 완주(H24) → M3 제출·발표(H30). 모든 이슈는 마일스톤에 속한다 — 안 속하는 작업은 지금 할 일이 아니라는 뜻
- **이슈 1개 = 담당 1명 = 2~4시간.** 담당이 2명 이상인 이슈는 만들지 않는다 — 책임이 증발하는 지점이다
- **여러 영역에 걸친 기능은 이슈가 아니라 목표다.** 약속(4장)의 경계선을 따라 역할별 이슈로 쪼갠다. 예: "추천 기능" = R3 점수(#) + R4 조립(#) + R2 API(#) + R1 화면(#) — 넷은 서로 기다리지 않고 가짜 데이터로 병렬 완성, 실제 결합은 통합 게이트에서
- **원인 모를 버그**("카드가 안 떠요"): 증상이 보이는 곳의 주인(화면이면 R1)이 담당으로 시작 → 원인 밝혀지면 실제 주인에게 넘긴다
- **30분 룰**: 30분 넘게 막히면 혼자 파지 말고 단톡에 공유 + 이슈에 `blocked` 라벨. 게이트 판정 때 blocked 목록부터 본다
- **보드**(Todo/Doing/Blocked/Done, 1인당 진행 중 1개): 같은 방에 있는 4명에게 보드는 **소통 수단이 아니라 기록 수단**이다. 결정은 입으로, 상태는 보드로. "이슈에 써놨는데요"는 소통이 아니다
- **스탠드업**: 4시간마다 5분, 서서. 직전 결과 / 다음 목표 / 막힘 여부만

## 6. 본선 30시간 — 역할별 계획

| 시간 | R1 화면 | R2 서버 | R3 데이터·점수 | R4 조립·AI |
|---|---|---|---|---|
| H0~2 | 환경 확인 | 배포 확인·깨우기 | 데이터 최신화 | AI 확인 + 단순 API 일부 인수 |
| H2~10 | 홈·추천 화면 (가짜 데이터) | 세션·추천 API | 점수 계산 v1 | 조립 v1 |
| **H10~12** | **통합1 — 전원.** 기준: ①배포 정상 ②점수 테스트 통과 ③추천 API 응답. 실패 시 H14까지 연장, R1은 가짜 데이터로 계속 진행 | | | |
| H12~20 | 상세·인증·기록 화면 + **대시보드**(가짜 데이터로 미리) | 인증·기록·대시보드 API | 점수 조정·지도 데이터 | AI 기록 생성·대체 문구 |
| **H20~24** | **통합2 — 전원.** 전체 완주 + 리허설 1차 + AI 저장분 채우기 + 로컬 복사. 이후 2인 1조 90분 교대 수면 | | | |
| H24~28 | 다듬기·화면 캡처 | 버그·비상 스위치 점검 | 대시보드 숫자 검수 | 발표 자료·데모 대본 확정 |
| H28~30 | **리허설 — 전원.** 온라인 1회 + 오프라인 1회 + 발표 연습 1회 | | | |

## 7. 시간이 없을 때 버리는 순서

1. AI 유사도 정렬 (키워드 매칭만으로 시연 — 기획서에도 2차로 명시돼 있어 방어 가능)
2. 대시보드 사각지대 지도 (히트맵·저유입 2종은 유지)
3. 영수증 인증 (업로드까지만 — 단, 발표에서 "소비 지표" 설명은 유지)
4. QR 카메라 (4자리 코드로 시연 — "어르신 배려 경로"라는 서사로 전환 가능)
5. 스탬프 연출 (적립 숫자만)

**절대 못 버리는 것**: 입력→추천→상세→인증→기록의 전체 완주, 그리고 만14세 확인·기록 삭제 버튼(개인정보 설계의 방어선).

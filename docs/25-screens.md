# 봄내마실 — 페이지별 기능 정의서

> R1(화면 담당)의 구현 기준 문서. 흩어져 있던 화면 관련 결정(문서·이슈 코멘트)을 화면 단위로 모은 것이다.
> 각 화면의 "관련 이슈"에 완료 조건이 있고, 여기 없는 동작이 궁금하면 10분 결정 프로세스(20-team 5-1)로.

## 0. 공통 규칙

- **디자인 토큰 (프로토타입 v2 기준, `design/prototype.html`)**: 주색 `#0E87C4`(파랑) · 짙은 배경 `#0B3A52` · 본문 `#1C262B` · 보조 `#5E6B72`~`#93A0A8` · 라인 `#CBD8DF`, 서체 Pretendard. 시각·레이아웃은 프로토타입을 따르되, **동작은 이 정의서가 우선** — 알려진 편차는 `design/README.md` 참조 (실시간 표기 금지·대시보드 별도)

- **개발 방식**: 전 화면을 목 JSON(#17)으로 서버 없이 먼저 만들고, 통합 게이트에서 실서버로 전환 (`VITE_USE_MOCK`)
- **기준 해상도**: 모바일 375px 우선 (심사위원 폰 QR 접속), 데스크톱은 대시보드만 우선
- **언어**: 존댓말, 낙인어 금지("저유입"은 시민 화면에 노출하지 않는다 — "숨은 가게", "새로 만나는 가게" 등으로)
- **포인트 잔액**: 홈·보관함 상단에 상시 노출. 적립 순간 +N 연출(간단한 애니메이션, 여유 없으면 토스트)
- **로딩**: 추천 계산 등 수 초 걸리는 곳은 스켈레톤 또는 진행 문구. 빈 화면 금지
- **오류 공통 문구**: "잠시 문제가 있었어요. 다시 시도해 주세요" + 재시도 버튼 (기술 용어 노출 금지)
- **localStorage 키**: `session_id`(영구 열쇠), `active_quest_id`(진행 중 퀘스트 — 이어하기용)
- **세션 무효 복구**: 전체 삭제 성공 시 두 키를 함께 제거한다. 서버가 "세션 없음"을 응답하면(삭제 후 재방문 등) 로컬 키를 폐기하고 첫 방문 모달을 다시 띄운다 — 죽은 열쇠로 재시도를 반복하게 두지 않는다

## 1. 홈 (입력)

**역할**: 첫 진입 관문. 만 14세 확인 → 조건 4종 입력 → 추천 요청.

| 요소 | 정의 |
|---|---|
| 첫 방문 모달 | localStorage에 session_id 없으면 표시. ① "만 14세 이상입니다" 체크(필수) ② 닉네임(선택, "실명은 쓰지 마세요" 힌트) ③ 개인정보 최소수집 한 줄 고지. 확인 → POST /sessions → session_id 저장 |
| 이어하기 배너 | `active_quest_id` 있으면 상단에 표시. started 상태: "진행 중인 퀘스트가 있어요 — 이어하기" → 상세(#30). **stamped 상태: "기록만 남기면 완주예요 (+60점)" → 기록 화면(#5)**. 배너·키 제거는 **기록 저장(완주) 또는 중단 시에만** — 인증 완료로는 지우지 않는다 |
| 관심사 | 칩 8종(운동·건강/문화·공연/공예·만들기/사진·미디어/요리·먹거리/학습·어학/자연·나들이/청소년·진로) 중 **최대 3개** 선택. 계약①의 enum 그대로 (#48) |
| 출발지 | **2단 선택**: ① 행정동(필수) — GET /zones(경로 보유 동만) ② 동 선택 시 그 동의 정류장 목록 펼침(선택, 기본값 "잘 모르겠어요", 가나다순+타이핑 필터 — GET /stops?zone=). 정류장 선택 시 그 정류장 기준으로 정확 계산, 미선택 시 접근성 점수표가 활동지별 최적 정류장 선택 + **카드·상세에 "○○ 정류장 기준" 표기**(추정임을 드러냄). 기획서 3-5 "행정동·정류장 단위 입력" 이행 — GPS 없이 위치 정밀도 확보 |
| 시간 | 현행: **시작~종료 시각 창 선택**(최소 60분). **#55 승인 시: 시간대 버튼 3개(오후/저녁/하루 종일)로 교체** — 승인 결과 확인 후 구현 |
| 예산 | 구간 버튼 5개: 무료만 / 1만 / 3만 / 5만 / 상관없음 (#26 코멘트의 값 그대로) |
| 추천 받기 | 4종 입력 검증 후 추천 화면으로. 미입력 항목은 버튼 비활성+안내 |

관련 이슈: #22, #48, #24 / 데이터: GET /zones, POST /sessions

## 2. 추천 (퀘스트 카드)

**역할**: 카드 3장 제시 — 데모의 첫 하이라이트.

| 요소 | 정의 |
|---|---|
| 퀘스트 카드 ×3 | 각 카드: 활동명·시간 요약 / 가게 미션 한 줄(사전 생성 문안) / 버스 한 줄("300번 · 약 12분 간격 · 25분") / **"환승 없음" 배지** / 예산 합계 "약 ~원 (버스 왕복 포함)" / 점수 구성 미리보기(5지표 미니 막대) |
| D-day 뱃지 | 신청형 활동은 "개강 D-n" (마감 아님 — 오인 금지 표기) |
| 가게 없는 퀘스트 카드 | 미션 줄 대신 "이번엔 활동만 즐겨요 — 기록으로 완주 (+60점)" 문구, 예산 합계는 활동비+버스 왕복만 |
| 보너스 가게 | #55 승인 시: 카드에 "+ 걸어서 3분, ○○도 들러보세요 (+10점)" 선택 미션 표시 |
| 다른 추천 보기 | **무료.** 기노출 제외 4~6위 반환. 소진 시 버튼 숨김 + "조건을 바꿔 다시 받아보세요" |
| 빈 결과 | 자동 완화(예산+30% → 관심사 확대 → 상시형 대체) 결과와 함께 "조건을 조금 넓혀 찾았어요" 안내. 완전 빈 화면 금지 |
| 뒤로가기 | 저장된 추천 스냅샷 재표시 — 재계산하지 않는다 |
| 로딩 | 스켈레톤 카드 3장 + "오늘의 춘천을 조합하고 있어요" |

관련 이슈: #23, #25, #27 / 데이터: POST /quests/recommend (스냅샷 저장)

## 3. 상세 (지도·경로·시작)

**역할**: 카드 하나의 전모 확인 → "퀘스트 시작" 결심.

| 요소 | 정의 |
|---|---|
| 지도 | 카카오맵. 마커 3종: 활동지 / 미션 가게 / 승·하차 정류장(**경험 장소 아님** — 아이콘·색으로 구분) + 경로선 |
| 활동 블록 | 상세 정보, 신청형이면 신청 안내 + "오늘 할 일: 신청·장소 미리 가보기·근처 가게 미션" |
| 버스 블록 | 노선번호·배차간격·소요시간 — "300번 · 약 12분 간격 · 25분 소요" 고정 표기 (실시간 도착 미사용 — 운영 로드맵) |
| 미션 블록 | 문안 + 인증 방법 안내(QR/코드/영수증). 가게 없는 퀘스트는 "이번엔 활동만 즐겨요 — 기록으로 바로" |
| 예산 블록 | 합계 "약 ~원 (버스 왕복 포함)" |
| **퀘스트 시작** | 버튼 → started 전이(시작 시각 기록) + `active_quest_id` 저장 → **수행·인증 화면(#4)으로 이동**. **진행 중 퀘스트가 이미 있으면 확인 모달**("기존 퀘스트는 중단돼요") → 기존 건 abandoned |
| started 재진입 | 이어하기로 다시 들어온 상세는 시작 버튼 대신 **"인증하러 가기" / "기록 쓰기" 버튼 2개** 표시 |

관련 이슈: #30, #47 / 데이터: GET /quests/{id}, POST /quests/{id}/start

## 4. 수행·인증

**역할**: 가게에서 스탬프 찍기 — 데모의 두 번째 하이라이트.

| 요소 | 정의 |
|---|---|
| 진행 요약 | 활동·가게·상태 표시 |
| 인증 3탭 | ① QR 스캔(카메라 — https 필수, 실패 시 ②로 유도) ② 4자리 코드 입력(고령·카메라 불가 경로) ③ 영수증: 사진 업로드 + 금액 입력(1,000~200,000원) |
| 성공 | 스탬프 연출 + **+40 적립**(#55 승인 시 보너스 가게 +10 별도) → 기록 화면 유도 |
| 기록만 남기기 | 하단 보조 링크 "인증 없이 기록만 남길래요" → 기록 화면(#5). 저장 시 "인증 없음" 뱃지, 완주 보너스 없음(+40만) |
| 이미 인증됨 | 에러가 아니라 성공 톤: "이미 적립된 퀘스트예요" (멱등 — 데모 중 에러 화면 금지) |
| 가게 불일치 | "이 퀘스트의 미션 가게는 ○○예요" + 재시도 무제한 |
| 영수증 안내 | "사진은 저장되지 않아요" 고지 (즉시 폐기 정책 그대로 문구화) |

관련 이슈: #31, #34, #20 / 데이터: POST /missions/{quest_id}/verify

## 5. 기록·보관함

**역할**: AI 기록 생성 → 저장 → 완주. 경험의 자산화.

| 요소 | 정의 |
|---|---|
| 문답 | 첫 질문 "이 기록을 어디에 쓸까요?"(포트폴리오/취미 아카이브/배움일지 — 기본값 취미 아카이브) + 고정 3문항(칩 중심, 각 200자, 전부 선택 입력). 입력란에 "실명·연락처는 적지 마세요" |
| 생성 | 로딩 문구 → 8초 초과 시 템플릿 초안 + "연결이 느려 기본 초안을 먼저 드려요". "다시 생성" 최대 2회 |
| 결과 | 제목 1줄 + 본문 300~500자 + 태그 3개. 저장 전 텍스트 수정 가능(저장 후 읽기 전용) |
| 저장 | **+40 적립, 스탬프도 있으면 완주 보너스 +20**. **가게 없는 퀘스트는 기록 저장만으로 완주 보너스 지급(합 60점)** → `active_quest_id` 제거, 이어하기 배너 소멸. **적립 조건: 문답 최소 1개 응답**(칩 1탭 충족) — 전부 비우면 저장은 되지만 적립 없음 + "한 가지만 골라주시면 포인트가 적립돼요" 안내 |
| 보관함 목록 | 기록 카드(제목·날짜·태그) + "인증 없음" 뱃지(스탬프 없이 저장한 건) + **칭호 뱃지(100점 도달 시 해금)** |
| 전체 삭제 | "내 기록 전체 삭제" 버튼 → 확인창: "모든 기록·스탬프·포인트가 삭제돼요. 개인 식별이 불가능한 통계는 유지됩니다" → DELETE /sessions |

관련 이슈: #32, #38, #35, #53 / 데이터: POST /records, GET /records, DELETE /sessions

## 6. 정책 대시보드 (춘천시청용)

**역할**: 추천 엔진 중간 산출물의 재활용 증명 — 데모 마지막 하이라이트.

| 요소 | 정의 |
|---|---|
| 지도 | 접근성 히트맵(동별 평균, 5분위 색) + 저유입 상권 포인트 레이어 토글. 여유 시 사각지대 레이어 |
| KPI 카드 4장 | 방문 전환율 / 저유입 추천 비중 / 평균 탐색 시간 / 실행 가능성 100% — 산식은 #36 코멘트 동결안. 분모 0이면 "—" |
| 각주 | "시범 운영 시뮬레이션 데이터 포함" (KPI 시드 #50 정직 표기) |
| 접근 | 데모용 공개 URL(무인증) — 심사 질의 방어 멘트: "운영 이관 시 시청 계정 인증 추가" |

관련 이슈: #33, #36, #12, #50 / 데이터: GET /dashboard/accessibility·inflow·kpi

## 7. 이 문서의 유지 규칙

- 화면 동작이 바뀌는 결정(②③급)이 확정되면 **이 문서를 같은 PR에서 수정**한다 — 정의서가 낡으면 만들지 않은 것과 같다
- 미확정 표시가 있는 항목(#55 등)은 결정 후 표시를 제거한다

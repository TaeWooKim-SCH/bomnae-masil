## 0-3. 행사(활동) 데이터 추가 수집처 — 문화재단 밖

현재 행사 소스는 춘천문화재단 하나뿐. 확장 수집처 (전부 공공데이터포털 무관):

| 수집처 | 방법 | 비고 |
|---|---|---|
| **🥇 춘천문화예술정보 모아봄** (cccf.or.kr/moa) | POST 폼 크롤 — 아래 스펙 참조. **8/1 필터 시 4페이지·최대 ~24건** (태우 발견, 7/31 분석) | **춘천 행사 통합 플랫폼** — 재단+타 기관+민간 혼합, 기간 2026-07~09 기준 90건+. 카드의 data-속성에 제목·기간·**전체 주소**·**행정동**·연령·카테고리·무료/유료·상태가 전부 있어 상세 페이지 불필요. 크롤 난도 최하 |
| 한국관광공사 TourAPI (api.visitkorea.or.kr) | 자체 포털 키 신청(자동 승인) → searchFestival, 지역=춘천 | 축제 표준 소스·좌표 포함 — 모아봄 보완용 |
| 춘천시청 문화행사·행사일정 페이지 | 크롤 또는 수기 (건수 적음) | 시 주관 행사 |
| 춘천 문화관광 사이트 (축제 안내) | 수기 | 막국수닭갈비축제 등 — 8/1 진행 여부 확인(#49) |
| 시립도서관·미술관·문화원 홈페이지 | 수기 | 상시형 씨드와 함께 |

**모아봄 크롤 스펙 (R3 — 30분 작업)**: `POST https://cccf.or.kr/moa` 폼 파라미터 `pageIndex`(1~N), `searchFromDate`/`searchToDate`(예: 2026-08-01 — **서버 측 날짜 필터**), `eventStatus`, `searchCategoryCode` 등. 응답 HTML의 `a.event-item` 요소가 카드이며 **data-속성이 전체 레코드**: `data-title`·`data-period`·`data-address`(도로명 전체 — 카카오 지오코딩 입력)·`data-regions`(행정동 — zones 매핑 직결)·`data-target`(연령)·`data-category`(공연/행사/전시)·`data-price`(무료/유료)·`data-status`·`data-image`. 정확한 요금 금액은 없음 → 유료는 null+"예매처 확인"(기존 규칙). 적재 시 기존 문화재단 크롤분과 제목 기준 중복 제거.

효과: 데모일(8/1) 활동 풀 = 모아봄 ~20건+ + 상시형 씨드 12건 (기존 "전시 2건뿐" 문제 해소). 상시형 씨드는 여전히 유지 — 모아봄은 행사성 콘텐츠라 도서관·산책 같은 상시형은 씨드가 유일한 소스.

## 4. 수집·관리 규칙

1. **스냅샷 원칙**: 시연일 기준으로 한 번 내려받아 고정본을 쓴다 (본선장에서 새로 받지 않는다). 원본 파일은 저장소가 아니라 **팀 드라이브에 공유**하고 `pipeline/snapshots/`는 `.gitignore` 처리돼 있다
2. **춘천 필터 선적용**: 전국 단위 데이터(특히 #9 인허가 — 수 GB급)는 내려받은 뒤 적재 전에 춘천만 걸러낸다. 안 그러면 DB 무료 용량(500MB)을 바로 초과한다
3. **종료된 것 걸러내기**: 기간이 지난 행사·강좌는 적재 단계에서 제외한다
4. **측정 이력 없음 = 저유입 추정 후보**: #4 실태 데이터에 없는 가게는 "데이터가 없다"는 이유로 저유입 확정하지 말고, 보수적으로 '추정 후보'로만 분류한다 (기획서에 약속한 편향 방지 원칙)
5. **온라인 활동 제외**: 강좌·프로그램 중 온라인 진행분(강좌명·내용에 온라인/비대면/줌/화상/원격)은 적재 시 제외한다 — 퀘스트는 "오늘의 외출 1회" 단위라 외출 없는 활동은 후보가 아니다 (기획서 KPI도 온라인을 분모 제외로 명시). ⚠ 장소를 암묵 좌표(학습관 등)로 채우는 경우 온라인이 통과할 수 있으니 좌표 부여 전에 이 필터를 먼저 적용
6. 데이터마다 **기준일·행 수·출처 URL**을 이 문서에 기록한다 — 심사 질의("이 데이터 어디서 났나요")에 문서로 답한다

# 봄내마실 — 서비스 개요

> 전원 필독. 이 문서 하나로 "우리가 뭘 만드는지" 같은 그림을 갖는 게 목적이다.
> 공식 제출본은 개발기획서 PDF이고, 이 문서는 그 요약이다.

## 한 줄 정의

**"오늘 뭐 하지?"를 입력하면, 춘천에서 오늘 할 수 있는 활동과 근처 가게 미션, 가는 버스편까지 묶어 '퀘스트'로 추천하는 웹 서비스.**

## 왜 만드나

- 춘천의 활동 정보(강좌·공연·축제·청소년 프로그램)는 사이트 5곳에 흩어져 있다. 찾다가 포기하는 게 보통이다.
- 골목상권은 새 손님이 들어올 이유가 없다. 지역화폐 할인은 "이미 온 손님"에게만 보상한다.
- 봄내마실의 답: **활동하러 가는 길 위에 가게 방문을 얹는다.** 소비하러 골목에 가는 게 아니라, 뭔가 하러 갔다가 소비하게 만든다.

## 퀘스트란

퀘스트 하나 = **활동 1개 + 가게 미션 1개 + 버스 이동경로 + 활동 기록 템플릿**의 완성된 패키지.

예시: "평생학습관 저녁 사진 강좌 수강 → 육림고개 카페에서 기록 미션 → 버스 몇 번, 몇 분 소요 → 끝나면 AI가 취미 기록 초안 작성"

## 이용 흐름 (이게 곧 데모다)

```
① 입력: 관심사 / 출발지(동네) / 가능 시간 / 예산
② 추천: 퀘스트 카드 3장 (점수 구성 미리보기)
③ 상세: 지도에서 활동 장소·가게·버스 경로 확인
④ 인증: 가게에서 QR 찍거나 숫자코드 입력 → 스탬프 적립
⑤ 기록: 간단한 문답 → AI가 활동 기록 초안 생성 → 보관함 저장
```

이 ①~⑤ 완주가 MVP(최소 완성 목표)다. **다른 건 다 버려도 이건 못 버린다.**

## 화면 6종

| 화면 | 내용 |
|---|---|
| 1 홈 | 첫 방문 시 "만 14세 이상" 확인 → 관심사·출발지·시간·예산 입력. 재방문 시 "진행 중인 퀘스트 이어하기" 배너 (퀘스트 수행이 몇 시간 걸려도 앱을 켜놓을 필요 없음 — 기록은 서버에, 열쇠는 브라우저에 남는다) |
| 2 추천 | 퀘스트 카드 3장. 신청형 강좌는 접수 마감 D-day 표시 |
| 3 상세 | 지도(활동지·가게·정류장·경로) + 버스 소요시간 + 예산 합계 |
| 4 인증 | QR 스캔 / 4자리 코드 입력 / 영수증 사진 → 스탬프 |
| 5 기록 | 문답 → AI 초안 → 수정·저장. "내 기록 전체 삭제" 버튼 있음 |
| 6 대시보드 | 춘천시청용: 접근성 지도 + 저유입 상권 표시 + 성과 숫자 |

## 추천 점수 — 이 서비스가 '지역경제' 과제인 이유

카드 순위는 5가지 점수의 합으로 정한다:

**상권 기여 30%** + 관심사 맞춤 25% + 버스 접근성 20% + 시간 적합 15% + 예산 적합 10%

가장 큰 가중치가 "손님이 덜 드는 가게(저유입 상권)를 우선 배치"에 걸려 있다. 시민 편의와 상권 살리기를 하나의 점수 체계에 넣은 것이 이 기획의 핵심 아이디어다.

## 고객은 둘이다

| 고객 | 받는 것 |
|---|---|
| 시민 | 탐색 시간 절약(사이트 5곳 → 3분), 실행 가능한 하루 계획, 활동 기록 축적 |
| 춘천시청 | 추천 엔진이 계산한 중간 산출물을 지도로 재활용한 정책 대시보드 — 활동 사각지대, 저유입 상권 |

## 미션 인증은 어떻게 하나 — 매장 협약이 전제가 아니다

인증 방법은 세 가지이고, 매장의 협조 수준에 따라 골라 쓴다:

| 방법 | 매장에 필요한 것 | 세는 지표 |
|---|---|---|
| QR 스캔 | 협약 매장: 우리가 준 QR 스탠드 비치 | 방문 |
| 4자리 코드 입력 | 같은 스탠드의 숫자 입력 (카메라 없어도 됨 — 어르신 배려 경로) | 방문 |
| 영수증 사진 + 금액 입력 | **아무것도 필요 없음** — 협약 안 된 매장도 커버 | 소비 |

- 협약이 안 된 매장도 영수증 인증으로 미션이 성립한다. **매장 확보가 서비스 성립의 병목이 되지 않게** 기획서에 설계된 부분이다 (시범 운영은 육림고개 등 1개 상권, 협약 20곳 내외로 시작하는 그림)
- 매장이 협약에 응할 이유: 서비스 안에서 무료로 노출되고, 방문·연령대 통계 리포트를 받는다
- **본선 데모에서는 협약이 전혀 필요 없다** — 시연용 QR·코드 스탠드를 우리가 인쇄해 가서 연출한다

## 사용하는 데이터 (전부 공개된 공공데이터, 10종)

- **버스**: 정류장 위치, 노선, 시간대별 승하차 인원, 실시간 도착(TAGO)
- **활동**: 공연·축제, 평생학습관 강좌, 청소년 프로그램
- **가게**: 상가·인허가 정보(영업 여부), 상권 이용자 실태(어디가 한산한지)
- **인구**: 행정동별 연령별 인구

정식 명칭·제공기관·활용처가 담긴 상세 목록은 [15-data.md](15-data.md) 참조 — R3의 수집 기준 문서다.

## 성과 목표 (심사 때 숫자로 보여줄 것)

1. 미션 방문 전환율 40% 이상 (스탬프 기록으로 측정)
2. 추천 퀘스트 중 저유입 상권 비중 50% 이상
3. 활동 탐색 3분 이내 (기존: 사이트 5곳에서 수십 분)
4. 추천한 이동경로의 실행 가능성 100% (버스로 실제 갈 수 있는 것만 추천)

## 개인정보 4원칙

1. **위치 추적 없음** — GPS를 쓰지 않고 동네를 직접 고른다
2. **만 14세 이상**만 이용 (첫 화면에서 확인)
3. **내 기록은 내가 삭제** 가능 (버튼 하나로 전체 삭제)
4. AI에게 **이름·소속을 보내지 않는다** — 활동 내용만 전달

## 일부러 안 만드는 것 (그리고 왜)

"이거 없어도 돼요?"라는 질문이 나오기 전에 — 아래는 빠뜨린 게 아니라 뺀 것이다:

| 안 만드는 것 | 왜 |
|---|---|
| 로그인·회원가입 | 심사위원이 QR 찍고 3초 안에 체험을 시작해야 하고, "수집 항목이 없어 유출될 것도 없다"가 우리 개인정보 설계의 방어 논리다. '내 스탬프·기록' 유지는 브라우저에 저장되는 세션 ID로 충분(사실상 비밀번호 없는 자동 로그인). 기기를 바꾸면 기록이 안 따라오는 한계는 인정 — 운영 단계에서 카카오 간편로그인을 얹는 로드맵으로 답한다 |
| 환승 포함 길찾기 | 환승 없이 가는 경로까지가 MVP (기획서 명시 — 환승 탐색은 고도화) |
| 영수증 자동 판독(OCR) | 사진 업로드 + 금액 입력까지만. 진위 검증은 고도화 과제로 정직하게 명시 |
| 네이티브 앱 | 설치 없는 웹이어야 QR로 즉시 시연 가능. 앱은 데모 가치 대비 비용만 크다 |
